# AGENTS.md — kmword

**PWA vocabulary app** — pure frontend, no build step, no bundler, no package.json.

## Architecture

- **Entrypoint:** `index.html` (HTML + all pages in one file).
- **Styles:** `styles.css`.
- **Scripts (IIFE, no module system):**
  - `js/fsrs.js` — vendored ts-fsrs 5.4.2 UMD build (FSRS-6 scheduler), exposes `window.FSRS`.
  - `js/word-freq.js` — 12k English word-frequency list (OpenSubtitles 2018, `window.WORD_FREQ` array, rank = index+1), generated by `build_word_freq.js`.
  - `js/wiktionary.js` — Wiktionary REST definition API client (`window.wiktionaryAPI`), fallback dictionary source; strips HTML markup to plain text.
  - `js/ecdict.js` — ECDICT CSV entry parsers + HTML renderer (`window.ecdict`), no network.
  - `js/dictionary-api.js` — multi-source online dictionary client (`window.dictionaryAPI`): FreeDictionaryAPI.com immediately + Free Dictionary API after a 700ms hedge, Wiktionary + Datamuse fallback, ECDICT local fallback, and `word_cache.en` caching; losing provider requests are aborted.
  - `js/stats.js` — statistics aggregation module (`window.statsUtil`): pure functions for Beijing-time day bucketing, FSRS state/stability/retrievability aggregation, review-log analysis, due forecasting, heatmaps and CSV export. No DOM, unit-testable in Node.
  - `js/db.js` — WordDatabase class + `window.wordDB` instance.
  - `js/ecdict-worker.js` — dedicated Web Worker for streaming `ecdict.csv` parsing (not a page script).
  - `js/novel-processor.js` — NovelProcessor class + `window.novelProcessor` instance.
  - `js/app.js` — WordLearnerApp class + `window.app` instance.
- **Load order (manifest in `<script>` tags):** `fsrs.js` → `word-freq.js` → `wiktionary.js` → `ecdict.js` → `dictionary-api.js` → `stats.js` → `db.js` → `novel-processor.js` → `app.js`.
- **Storage:** IndexedDB `WordLearnerDB` (v12), stores: `words`, `word_lists`, `user_progress`, `new_words`, `daily_plan`, `learning_history`, `novels`, `settings`, `word_cache`, `listening_files`, `audio_segments`, `ecdict`, `ecdict_meta`, `review_log`, `sentence_audio`.
- **PWA:** `sw.js` (cache-first static, network-first for Dictionary APIs), `manifest.json` (scope `/kmword/`).
- **Icons:** `icons/` — `icon.svg` (rounded, purpose `any`) + `icon-maskable.svg` (full-bleed) are the sources; PNGs (`icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png`, `favicon-32.png`) are generated by `icons/build_icons.py` (needs `cairosvg`). The Android adaptive icon (`drawable/ic_launcher_foreground.xml` + `drawable/ic_launcher_background.xml` gradient) mirrors the same book motif.
- **Deployment:** GitHub Pages at `https://unplage.github.io/kmword/`.
- **Android wrapper:** `android/` is a separate Gradle/Kotlin project for a WebView-based Android app; not part of the PWA frontend.

## API dependencies

- **FreeDictionaryAPI.com** (`freedictionaryapi.com`) — primary online dictionary source, no key, CORS enabled, 1,000 requests/hour/IP. Data is Wiktionary/Wiktextract-derived under CC BY-SA 4.0. Responses are rich (`entries[].senses[]`, examples, quotes, synonyms, IPA, forms); not-found is HTTP 200 with `entries: []`.
- **Free Dictionary API** (`api.dictionaryapi.dev`) — secondary source, starts after a 700ms hedge, no key. The upstream origin is intermittently unavailable (HTTP 522/530); network/5xx failures are not cached.
- **Wiktionary REST API** (`en.wiktionary.org/api/rest_v1/page/definition`) — automatic fallback, no key, CORS `*`. `js/wiktionary.js#query` returns parsed data / `null` (transient) / `false` (definitive 404). It can be unreachable from mainland China.
- **Datamuse** (`api.datamuse.com`) — lightweight emergency fallback (`/words?sp=…&md=dpfr&ipa=1`), no key until 2027-02-01, short definitions only. Free tier is 100,000 requests/day.
- **Pronunciation audio** — FreeDictionaryAPI.com returns IPA but no audio files. `js/dictionary-api.js#getAudioUrl` generates a Youdao `dict.youdao.com/dictvoice?audio=…&type=2` fallback (US pronunciation); `speakWord`/`speakCurrentWord` try that audio first, then fall back to browser/Android TTS if playback fails.
- **Online lookup chain** (`js/dictionary-api.js#fetchWordData`): FreeDictionaryAPI.com immediately + Free Dictionary API after a 700ms hedge (3.5s timeout each) → Wiktionary immediately + Datamuse after a 350ms hedge → local ECDICT → fallback. Losing provider requests are aborted once a source wins, including delayed requests that have not started. Successful results are cached in `word_cache.en`; network/5xx failures are not cached. `probe()` checks FreeDictionaryAPI.com and Datamuse for general connectivity instead of relying on `api.dictionaryapi.dev`.
- **Novel extraction** uses the same shared chain via `window.dictionaryAPI.fetchWordData(word, { persist: false, memory: false, signal })` and keeps its own in-memory `dictionaryCache`.
- **Merriam-Webster API** (`dictionaryapi.com`) — optional, configure `mwDictKey` + `mwThesKey` in Settings. Free registration at https://dictionaryapi.com/register/index.htm.
- **Browser SpeechSynthesis** — built-in TTS used by the reading module. Configurable voice (named) and speed via Settings. No API key needed.
- **Xiaomi MiMo TTS API** (`api.xiaomimimo.com`, model `mimo-v2.5-tts`) — optional streaming cloud TTS for the reader (full-article reading). Configure `ttsEngine = mimo` + `mimoApiKey` + `mimoVoice` in Settings. Streaming returns base64 PCM16 (24 kHz mono), played via Web Audio API.

## Word list import

Upload supports `.txt`, `.md`, `.html`. Three modes:
- **单词模式 (word)** — extracts words from text.
- **阅读模式 (reading)** — saves file as-is for in-app reading with TTS + word lookup.
- **听力模式 (listening)** — saves file and generates segmented TTS audio (MiMo), resumable.

TXT files in this repo follow a numbered-list format (header of "Level4_2 单词列表", "共 N 个单词", `====` divider, then `   1. word`). Exception: `雅思260314-3427.txt` is one-word-per-line, no header.

## Novel word extraction (单词模式)

`novel-processor.js#processNovel(text, options)` pipeline: tokenize (keeps case for proper-noun detection) → surface counting → lemmatization (irregular verb/noun table + contraction/elitic rules + suffix rules validated against a lexicon of all in-text forms + word-freq list + allowed list) → filters → sort by occurrence.

Filters (options): `minFrequency` (slider, default 3), `skipRank` (UI select: 0/2000/3500 default/5000/8000 — drops words with OpenSubtitles rank ≤ N), `allowedWords` (UI select 「仅保留词表」→ words of a chosen DB word list; when set, only those words are kept and they bypass the COMMON_WORDS / skipRank / proper-noun filters), `excludeProperNouns` (default true; drops lemmas that are never lowercase and are capitalized at least once mid-sentence — sentence-initial capitals don't count as evidence — unless in the allowed list), hard-coded `COMMON_WORDS` set (unless in allowed list), length 3–20.
Difficulty: rank-based bands (≤2000→1, ≤4000→2, ≤6000→3, ≤9000→4, else 5); words outside the freq list fall back to the legacy heuristic. `extractSentence` matches the lemma or any of its recorded surface variants.
Caveat: for exam-list TXT imports (专四/专八/托福/雅思) select 「不跳过」 and min frequency 1, otherwise common list words get filtered out.

## Word lookup cache buttons

- 查词弹窗 has two extra buttons 「韦氏词典（缓存）」/「AI 分析（缓存）」, shown only when the word has a corresponding `word_cache` entry (checked in `refreshLookupModalCacheButtons`).

### 导入 AI 释义缓存（设置 → 数据管理 → 导入 AI 释义缓存）

支持 `.json`（数组或 `{word: content}` 映射）和 `.jsonl`（每行 `{word, content, cachedAt?}`），可选 `.tsv`（`word<TAB>content`）。导入时：
- 默认只写入**不存在** AI 缓存的单词；勾选「覆盖已有 AI 缓存」会覆盖。
- 分批写入 `word_cache`，支持 `取消`；已写入的条目不会因停止而丢失，下次运行自动续跑。
- 导入后，查词弹窗对应的单词会出现「AI 分析（缓存）」按钮，点击直接展示缓存的 AI 释义，**不影响实时 AI 查询功能**。

## ECDICT external dictionary

- Settings → 数据管理 → 「导入 ECDICT 词典」accepts the official `ecdict.csv` (~63MB, ~770k entries; ~150MB IndexedDB). Parsing runs in `js/ecdict-worker.js` from `File.stream()` with 1000-record batches and ack backpressure; main thread writes each batch via `db.importEcdictBatch`.
- Import asks to confirm (and to overwrite when already `ready`), checks `navigator.storage.estimate()` against a 300MB free-space warning, and calls `navigator.storage.persist()` **without awaiting** (Firefox can leave it pending until a gesture).
- `ecdict_meta.status` transitions `importing` → `ready`, or `incomplete` on error/cancel/leave. Incomplete imports keep written rows; re-import clears and restarts, delete clears both stores.
- Word lookup modal shows an 「ECDICT」button only when meta is `ready` with `count > 0`; `db.getEcdictEntry` tries the lowercased word plus apostrophe/punctuation variants. Rendering (`js/ecdict.js`) escapes all text, splits literal `\n`, badges POS/domain/exam tags, makes English words clickable, and collapses long English definitions (more than 6 senses, or >1800 chars) into `<details>`.
- ECDICT is **not** included in data export/backup. `db.clearUserData()` (used by backup import) clears learning stores but preserves `ecdict`/`ecdict_meta`; manual 「清空所有数据」 deletes the whole database including ECDICT. MIT attribution is shown at the bottom of every entry.
- Repo root ships `ecdict.csv` (official ~63MB dump) + `ECDICT-LICENSE.txt` (MIT, Copyright 2025 Linwei) for direct download/import; the CSV is not listed in `sw.js` precache.

## Listening module

- TTS generation chunks the article at **paragraph boundaries** (deterministic `TextChunker.splitText`, ~3 min floor / 5 min target / 6 min cap; oversized single paragraphs are split by sentence), saves one `audio_segments` row per part, and updates `listening_files.status`/`generatedSegments` per segment.
- Generation is **resumable**: incomplete files (`status === 'generating'`, `generatedSegments < segmentCount`) can be continued from the listening list (「继续生成」button) or via the startup `confirm` prompt. Generation aborts on `pagehide`/`beforeunload` (via `_abortListeningGeneration`); deleting the listening file removes it and its segments.
- Voice + style (preset audio tags like `(温柔)` or a custom `role:user` instruction) are resolved at generation start and persisted on the file (`ttsVoice`/`ttsStyle`/`ttsStyleCustom`) so resume stays consistent. The reader's MiMo full-article TTS reuses the same `mimoStyle`/`mimoStyleCustom` settings.
- Download: player toolbar downloads a merged full WAV (`TTSGenerator.mergeWavBlobs`, header-stripped PCM concatenation); each segment in the list can be downloaded individually.
- Player restores last playback position (`lastSegmentIndex` + `lastSegmentTime`) on entry; position is saved on pause/segment-end/leave and throttled every ~3s during playback.

## 统计页（statistics）

- 统计页由 `js/stats.js`（纯函数聚合）+ `app.js#loadStatsPage`（取数与渲染）组成，图表全部是手写 div/CSS，无第三方依赖。
- **统一口径**：所有"天"都按 `Asia/Shanghai` 计算（`statsUtil.dayKey`），与连续天数、每日计划一致；旧的 `getLearningStats()`（UTC 分桶）不再用于统计页。
- **P0 FSRS 仪表盘**：今日学习（`getTodayHistory`，北京时间当天）、已学单词、成熟词（stability ≥ 21 天）、平均保持率（对 Review 卡调 `srs().get_retrievability` 加权平均，并与 `fsrsRequestRetention` 对比）、真实回忆率（`review_log` 中 rating ≥ Good 占比）、待复习/积压数、记忆状态分布（New/Learning/Review/Relearning）、稳定性分布直方图、未来 14 天复习负荷预测（对比 `plan.reviewGoal`）。
- **P1 记忆分析**：实际回忆率 vs FSRS 理论曲线（按 `elapsed_days` 分桶对比 `srs().forgetting_curve`）、四档评分分布与平均间隔、难度 × 回忆率、易忘词 Top 10（点击跳转查词）。
- **P2 行为维度**：学习时段热力图（0–23 时）、近 26 周活跃热力图、词库维度表格（总词数/已学/成熟/易忘/待复习/平均遗忘）。
- 时间范围切换（7/30/90 天）只影响"区间型"指标（回忆率、评分分布、日志相关），FSRS 状态类指标始终反映当前全量；可导出统计 CSV。
- `app.js#init()` 会在网络探测之前先 `bindEvents()`，保证首屏即可交互；初始化完成后 `app._initialized = true`。

## FSRS spaced repetition

- Scheduling uses vendored ts-fsrs (FSRS-6, `js/fsrs.js`); `db.js#updateProgress(wordId, grade)` accepts a grade (1–4 / `again|hard|good|easy` / legacy boolean) and maps it to Rating Again/Hard/Good/Easy. Parameters: learning steps `1m`/`10m`, relearning `10m`, fuzz on — configured in `db.js#srs()`.
- **Four-grade UI:** 认词模式有四个按钮（不认识 / 困难 / 认识 / 简单）。快捷键 `1`/`←`=Again、`2`/`→`=Good、`3`=Hard、`4`=Easy。拼写模式自动判定：正确=Good，「我不会」=Again。
- **Configurable retention:** `fsrsRequestRetention` setting (0.85 / 0.9 / 0.95) → `db.js#loadSrsConfig()` rebuilds the scheduler. 0.95 = 考前冲刺（间隔更短），0.85 = 长期记忆（间隔更长）。
- **Custom parameters:** `fsrsParams` setting holds 21 weights (JSON array or comma/space separated) → passed to `generatorParameters({w})`; the library clips/migrates them. Applied via Settings → 记忆算法 → 应用参数.
- **Review log:** every review writes one row to the `review_log` store (`db.js#addReviewLog`) with rating/state/due/review/elapsed_days/scheduled_days/stability/difficulty/last_elapsed_days. Settings → 记忆算法 → 导出 CSV produces the official FSRS review-log format for `fsrs-analyzer`; the optimized weights can be pasted back into 自定义参数.
- **Learning steps are respected:** Learning/Relearning cards are no longer re-shown immediately; they wait for their FSRS due time and appear in the 「待复习」 tray with a countdown (`app.js#scheduleLearningCard` / `tickPendingLearning`). If the session ends first, the card stays due in IndexedDB and is picked up next session.
- **Local day boundary:** `js/fsrs.js#dateDiffInDays` is patched to use local calendar dates (upstream uses UTC dates, which shifts intervals by a day for UTC+8 users). Do not overwrite this patch when updating the vendored library.
- **Leech:** `lapses >= 8` marks the card `isLeech`, auto-adds it to 生词本 and shows a ⚠️ 易忘词 badge (`db.js#updateProgress`, threshold `LEECH_THRESHOLD`).
- `maximum_interval` is capped at 3650 days.
- Legacy SM-2/familiarity records are migrated on their next review (`db.js#cardFromProgress`) using the official fsrs-rs formulas: stability = interval at 90% retention, difficulty derived from easeFactor; records with `repetition === 0` become New cards.
- `familiarity` (0–5, ≥4 "mastered") is only used for display/stats; it no longer drives scheduling.
- Recognition and spelling modes share one progress record.
- Backup import preserves all `user_progress` fields (FSRS state included) and the `review_log` history (backup version 3.3).

## 例句朗读（sentence audio）

- 释义例句、卡片例句、MW 例句旁有 🔊 按钮（`app.js#examplePlayButton` 生成的 `.example-play`），点击即朗读；**ECDICT 释义不加按钮**。
- 事件委托：`app.js#bindEvents` 在 `document` 上监听 `.example-play`（不用 inline onclick，避免例句里的引号破坏脚本）；`data-sentence` 存例句原文（HTML 转义），朗读前再做 300 字符截断与控制字符过滤（`app.js#sanitizeSentence`）。
- 引擎选择 `app.js#resolveSentenceEngine`：`auto`/`system`/`mimo`/`follow`（见设置 `sentenceTtsEngine`）。MiMo 走 `mimoSpeak`（`collect` 回调收集 PCM 分片），失败自动降级到系统 TTS（`app.js#speakSentenceSystem`，浏览器 SpeechSynthesis / Android `AndroidTTS` 桥）。
- MiMo 成功的例句音频写入 `sentence_audio` 缓存（`db.js#saveSentenceAudio`），下次同句直接 `mimoPlayPcm` 播放、不再请求云端；系统 TTS 不缓存。缓存上限 40 条 / 单条 ≤600KB。
- 播放会**打断全文朗读**（先 `stopReaderTTS()`），与单词发音行为一致；播放中按钮加 `.playing` 状态，结束/失败后复位。
- 与 `makeClickable` 兼容：`skipTags` 含 `BUTTON`，按钮不会被拆成可点击单词，也不会误触发查词弹窗。

## Settings (IndexedDB keys)

`autoPlaySound`, `showPhonetic`, `autoNextWord`, `theme`, `fontSize`, `mwDictKey`, `mwThesKey`, `learningMode`, `readerFontSize`, `currentListId`, `lastStudyDate`, `learningStreak`, `ttsVoice`, `ttsSpeaker`, `ttsSpeed`, `ttsEngine`, `mimoApiKey`, `mimoVoice`, `mimoStyle`, `mimoStyleCustom`, `playerSpeed`, `llmModel`, `llmWebSearch`, `fsrsRequestRetention`, `fsrsParams`, `sentenceTtsEngine`.

- `llmModel` — GLM model name (default `glm-4.7-flash`). User-configurable text input; empty = default.
- `llmWebSearch` — Boolean toggle for AI web search via GLM `web_search` tool.
- `ttsEngine` — reader full-article TTS engine: `system` (browser) or `mimo` (MiMo cloud). Word pronunciation always uses system TTS / dictionary audio.
- `mimoApiKey` — Xiaomi MiMo API key for `mimo-v2.5-tts`.
- `mimoVoice` — MiMo preset voice ID (`mimo_default`, 冰糖, 茉莉, 苏打, 白桦, Mia, Chloe, Milo, Dean).
- `mimoStyle` — MiMo pronunciation style preset (`standard`, 温柔, 活泼, 严肃, 平静, 磁性, 深沉, `custom`). Presets become audio tags like `(温柔)`; `custom` uses `mimoStyleCustom` as a `role:user` instruction.
- `mimoStyleCustom` — free-text style instruction used when `mimoStyle === 'custom'`.
- `playerSpeed` — listening player playback speed (0.5–2, step 0.1), persisted across sessions.
- `fsrsRequestRetention` — FSRS target retention (0.85 / 0.9 / 0.95, default 0.9); higher = shorter intervals.
- `fsrsParams` — custom FSRS-6 weights (JSON array or comma/space separated, ≥19 numbers); empty = official defaults.
- `sentenceTtsEngine` — 例句朗读引擎策略：`auto`（默认，有 MiMo Key 用云端否则系统语音）/ `system` / `mimo`（默认语音）/ `follow`（跟随全文朗读引擎）。

## Data export/import

- Export via Settings → downloads JSON (`word-learner-backup-<date>.json`), includes learning stores, `word_cache` (MW/AI/online `en` caches) and the FSRS `review_log` history but **not** the external `ecdict`/`ecdict_meta`. Import overwrites all learning data (double confirm) via `db.clearUserData()` and restores `word_cache` records (`wordCache` field in backup, v3.2+; older backups without it are still accepted) plus `reviewLog` (v3.3+); an installed ECDICT dictionary is preserved.
- Manual clear data (Settings 「清空所有数据」) deletes the whole IndexedDB database, including ECDICT.
- Clear data: `clear2.html` (scoped to `kmword` prefix) or `clear3.html` (scoped to current origin).

## Helper scripts

`extract_txt.py` — converts `kajweb/dict` JSONL to numbered TXT. Edit filenames in the script, then run manually.

`build_word_freq.js` — downloads the OpenSubtitles 2018 frequency list (hermitdave/FrequencyWords, MIT) and regenerates `js/word-freq.js` (top 12000, `node build_word_freq.js`).

`build_ai_gloss.py` — batch-generates AI glosses for a word list via `opencode serve` (default free `opencode/mimo-v2.6-flash-free`, no user API key), appending results to `ai_gloss_toefl.jsonl` (JSONL, one `{word, content, model, cachedAt}` per line). Supports `--limit`, `--workers`, stop/restart without data loss (`touch ai_gloss.stop` to stop; rerun to resume). Output can be imported via Settings → 数据管理 → 导入 AI 释义缓存.

`icons/build_icons.py` — regenerates the PNG icons (PWA + Android mipmaps) from `icons/icon.svg` / `icons/icon-maskable.svg` (`pip install cairosvg`, then `python3 icons/build_icons.py`).

`sw.js` (`CACHE_VERSION`) must be incremented whenever `js/app.js`, `js/dictionary-api.js`, `js/fsrs.js`, `js/stats.js`, `index.html`, or `styles.css` are modified. Same for the Android copy at `android/app/src/main/assets/sw.js`. Check before syncing to GitHub. Current: v50.

## Quirks

- **Timezone:** Learning streaks use `Asia/Shanghai` (Beijing time), not device local time (`js/db.js:960`).
- **Word normalization:** All words lowercased + `.trim()`-ed before storage or lookup.
- **`new_words` store:** `wordId` primary key prevents true duplicates; JS does manual dedup before `put()` to avoid overwriting `addedAt`.
